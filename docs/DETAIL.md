# 本地账本（dsh-ledger）

## 它是什么

`dsh-ledger` 是 DSH 里的**本地复式账本**：账本只存在你自己的机器上，是标准的纯文本 Beancount；Agent 读账单、生成待确认记录，你批准或驳回，到期核对余额。

- **本地**：没有服务、数据库或账号，账本只在你自己的目录里。
- **纯文本**：`main.bean` / `account/*.bean` / `trans/*.bean` 可以直接读，任何 Beancount 工具都能打开，也能用 Git 备份。
- **复式**：五类科目树、对账闭环、权益调整，每笔交易都是标准复式分录。

交易写 `trans/collect.bean`，对账写 `trans/reconciliation.bean`，`main.bean` / `account/*.bean` 是账户与结构配置。

条目可以带 `time` / `uuid` / `status` 等 metadata，由 Agent 从账单带入、由 Core 写入：

```text
2026-10-30 * "月梅早餐" "收款方备注:二维码收款付款方留言:早餐玉米"
  time: "07:23:07"
  uuid: "53110002338023202610300670672032"
  status: "WeChat - 已转账"
  Expenses:Food:Breakfast  3.50 CNY
  Assets:Savings:Web:WechatFund  -3.50 CNY
```

metadata 可选、缺失不阻塞；只影响新条目，不回填历史。

## 开始使用

首次打开时点「安装 / 修复账本引擎」，插件会用内置运行时在本地离线准备好引擎（不需要安装 Python），然后创建账本（填名称、选空目录），或直接打开已有 `main.bean` 的目录。

## 三个入口

### 审核

- **待对账**：按账户设置的对账周期列出到期、逾期或未对账的资产/负债账户；
- **待审核**：Agent 或补记产生的草稿。默认层显示日期、商户与描述、分类/资金两条分录与金额、阻塞问题和批准/驳回；账单原文在「详情」里，点描述或资金账户即可修改，失焦自动保存。未分类不阻塞批准，批准时按金额归入 `Expenses:Uncategorized` / `Income:Uncategorized`；金额、日期需调整请驳回重提。
- **批次**：Agent 一次导入是一个批次。批次卡显示来源、条数、跳过行和行数核对（`90/90 行已处理`：每行都有草稿或跳过记录，没有静默漏行）。可整批批准或驳回。
- **异常**：未分类、退款、待确认收货、资金账户未解析都会在批次里单列；资金账户未解析时不会被兜底，必须先批准开户或改选账户。
- **原始行**：草稿卡的「详情」里是「账单原文」（`source.evidence`，字段来自账单原文），方便核对描述与资金账户；勾选「只看异常」时自动展开。它只作参考，不写入账本。
- **补记**：次级入口，用于现金、转账、收入等没有来源的条目；只填金额、日期、描述、资金账户，不要求分类，保存后仍进草稿队列。

只开放描述和资金账户，是因为这两项直接决定可信且必须由人判断：资金账户错，余额与断言就对不上现实；描述错，条目就认不出。金额/日期是账单事实，分类/标签是解释层；把它们挡在面板外，人只做必要的判断，认知负荷最低。

### 对账

- 打开表单先显示预期余额、上次对账，以及本次是新建还是更新；
- 你只填**实际余额**；差额非 0 时才出现「差额分配」，没分完的默认记入权益调整；
- 提交时会确认预览之后账本没有被改动；校验通过才写入，失败不会改动账本；
- 同一个对账日期再次提交会更新最近一次记录，旧记录标记为已替换；更早期间不可改；
- 对账后仍可补记该日期之前的草稿，差额会自动平账。

### 账户

- 五类树：Assets / Liabilities / Equity / Income / Expenses；分类是可选解释层，真实资产/负债 + 兜底账户才是可信核心；
- 能否记账取决于账户是否已开立：资产/负债的分组节点只是分类，只有最末级账户可编辑、可记账、可对账；支出/收入的分组本身也可以记账；
- 资产/负债的最末级账户显示当前余额（只读）；余额为 0、有成本或持仓、支出/收入/权益不显示金额；
- 别名就地编辑；资产/负债的最末级账户可改周期或在详情内对账，有子账户时不能改周期；
- 新增账户走弹窗（路径 + 别名），默认使用账本币种，开立日默认为当天。

## 为什么可信

- Core 是唯一写者：Agent 只能提交草稿，不能直接改账本；
- 你批准后，整本账先校验，通过才写入；
- 校验失败时账本保持原样，不会写一半；插件不改写、不重试、不兜底；
- 兜底账户只决定「记到哪」，不绕过 `bean-check` 与 `balance` 断言。

## Agent 接口

插件注册四个只提案工具：`ledger_context`（账本与账户目录）、`ledger_propose_batch`（提交一个批次，含草稿、跳过行与结构操作）、`ledger_submit_operations`（单独提交结构操作）、`ledger_queue`（只读待审队列）。工具不能批准或驳回；批准在面板里。账本根目录的 `AGENTS.md` 写明了批次 schema 与字段语义。

## 数据与备份

```text
ledger/
├── main.bean
├── account/*.bean
├── trans/collect.bean
├── trans/reconciliation.bean
├── documents/            # 报告与原始账单，可删
└── .ledger/              # 草稿、批次、锁、审计、对账历史
```

账本真相只在 `.bean`；`.ledger/` 可删，但会丢草稿与审计。`documents/` 放报告与原始账单，不属于账本真相，可删。Git 忽略 `.ledger/`、`.venv/`、`documents/`，交易与对账文件必须跟踪；Core 不自动提交。

## 边界与限制

- Core 是唯一写者；插件不含账本规则，不直接写文件。
- Agent 只能提交草稿/结构提案/批次，批准由人触发；同 OS 用户 + 全 shell 下仍可绕过 `AGENTS.md` 改文件。
- 默认单币种；多币种账户不对账。
